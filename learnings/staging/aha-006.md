## Pattern

`open file://` URLs from Claude Code in a cmux split-pane layout = inline visual verification without context-switching. The browser renders on the right while the terminal stays on the left. Visual artifacts (HTML graphs, reports, screenshots) become part of the coding loop, not a separate step.

## Evidence

- [eureka-009]: Static HTML knowledge graph — opened inline during development, user saw the D3.js graph immediately while reviewing code changes in the terminal
- This session: Added hooks layer to graph, opened in browser, took screenshot, verified visually — all without leaving the terminal flow

## Implication

When building visual artifacts (HTML reports, knowledge graphs, diagrams), proactively `open` them in the browser so the user sees results immediately in their adjacent pane. This makes visual verification a zero-friction part of the development loop rather than a manual step.

## When to Apply

- After generating any HTML file (reports, visualizations, graphs) → `open` it
- After modifying existing HTML artifacts → `open` to verify
- When the user needs to visually confirm UI changes → screenshot + open
- Any time you'd say "you can open this file to verify" → just open it instead
