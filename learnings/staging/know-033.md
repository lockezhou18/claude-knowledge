## Context
When building agent productivity systems, there's an S-curve: foundation → rapid growth → diminishing returns → steady state. The inflection point is when the user asks "how do we iterate" instead of "what should we build next."

## Guidance
When [the system has 20+ skills, 30+ insights, multiple hooks and the user shifts from "build more" to "use what we have"]:
- **Stop adding, start watering.** No new skills unless real friction demands it.
- **Feed the data layer** — run /checkpoint during real work, /compound at milestones. The DIKW pyramid needs data at the bottom to flow upward.
- **Let the scoring system decide** what's worth keeping. Insights that get used graduate. Insights that don't get pruned. Skills that aren't invoked get deprecated.
- **Measure after 10 real work sessions** — compare /insights reports. Did wrong-approach count drop? Did any skills go unused?
- **Then prune** — remove 0-invocation skills, archive 0-use-count insights, simplify redundant rules.

## When to Apply
When any compound learning / agent productivity system reaches the diminishing returns phase. The signal is shifting from coverage to signal-to-noise ratio.
