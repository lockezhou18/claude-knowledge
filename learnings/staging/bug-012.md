## Anti-pattern: Serial confident-but-wrong conclusions in CSE investigations

**Symptoms:** Agent asserted 4 different root causes in sequence, each with confident tone, each wrong:
1. "Missing role assignments" (queried wrong table)
2. "Missing PurchasedHiringPlatformFeatures" (contract type already grants it)
3. "Wrapped jobs can't be edited" (working case is also wrapped)
4. "No backend difference" (didn't check lix, JobAdminSettings, canEdit full logic)

**Root Cause (metacognitive):** Each time data was consistent with a hypothesis, agent treated it as conclusive and asserted it. Never compared working vs non-working cases early. Made prod data changes before understanding the system.

**Fix:** 
- NEVER assert root cause — only present ranked hypotheses with likelihood
- Compare working vs non-working cases as STEP 1
- Read the full evaluation code path before proposing data fixes
- "Consistent" ≠ "conclusive" — multiple hypotheses can be consistent with same data

**Prevention:** Updated CLAUDE.md rules and feedback_checkpoint_prompting.md. The word NEVER is in rule 1.
